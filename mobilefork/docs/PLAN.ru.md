# Krita Mobile (неофициальный форк) — план работ

Состояние на 05.10.2026. Базовая версия: upstream `master` (5.4.0-prealpha, Qt 5),
коммит `c9c44bee` («Added Bayer dithering option to Gradient Tool»).

## 1. Что выяснилось на этапе исследования

**Сборка под Android.** Upstream собирает Android-версию на Qt 5.15 со своими
патчами (масштабирование интерфейса, планшетные события и т. п.). Все
зависимости (Qt, KDE Frameworks, FFmpeg, MLT, libmypaint, OCIO, …) KDE заранее
собирает и хранит в реестре пакетов invent.kde.org
(`teams/ci-artifacts/krita-android-arm64-v8a`). Сам Krita собирается скриптом
`run-ci-build.py`, APK — `build-tools/ci-scripts/build-android-package.py`
(androiddeployqt + Gradle, NDK 27.3, SDK 36). Это можно повторить на
бесплатных раннерах GitHub: компилировать придётся только Krita.

**Запрет для телефонов.** В `AndroidManifest.xml` стоит
`normalScreens="false" smallScreens="false"`: Google Play не показывает
приложение телефонам. Других проверок в коде (Java/C++) нет. На телефонах
Krita к тому же сама включает масштаб 2–3×, из-за чего интерфейс огромный.

**Мобильная работа upstream.**
- *Krita Sketch* (2012) удалён из кода много лет назад, использовать нечего.
- *Прототип Тимоте Жье* (MR !2417, июнь 2025): QML/Qt 6, «это прототип, он
  не подключён к коду Krita» — рисовать в нём нельзя, холст встроить пока не
  удалось.
- *План 2026*: перевести параметры инструментов на QML, чтобы делить их между
  мобильной и настольной версиями; Agata улучшает текущий интерфейс для
  планшетов. Krita 6 (Qt 6) пока экспериментальная, Android по-прежнему Qt 5.
- В коде уже есть основа, которой я воспользуюсь: QML-виджеты внутри обычного
  интерфейса (`qmlmodules/`, `KisQQuickWidget`), сенсорные жесты
  (двухпальцевое касание = отмена и т. п., `kis_touch_shortcut`),
  командная панель с поиском (`KisMainWindow::openCommandBar`), Android-код
  для полноэкранного режима, автосохранения, экспорта видео через MediaCodec.

**Инвентарь** (собран скриптом `mobilefork/tools/extract_inventory.py`,
результат в `mobilefork/inventory/`):

| Что | Кол-во |
|---|---|
| Действия из `.action`-файлов | 691 |
| Действия, создаваемые только в коде | 9 |
| Стандартные действия KDE (KStandardAction) | 28 |
| Из них размещены в меню/панелях | 255 |
| Докеры (панели) | 29 + параметры инструмента + панель инструментов |
| Инструменты | 35 |
| Фильтры | 48 (+ G'MIC) |
| Генераторы слоёв заливки | 5+ |
| Движки кистей | 16 |
| Фильтры импорта/экспорта файлов | 41 |
| Классы слоёв и масок | 18 |

473 действия не стоят ни в одном меню (у 170 из них есть горячая клавиша) — они доступны только через
горячие клавиши, контекстные меню докеров или командную панель. На телефоне
без клавиатуры они пропали бы. Поэтому всё должно быть доступно через
сгруппированные листы и поиск по командам; инвентарь — список для проверки.

**Что upstream уже отключает на Android** (не я — это надо будет решить, а не
молча оставить):
- Python-скрипты и плагины (`pykrita`) — в Android-зависимостях нет
  PyQt/Python;
- докер Small Color Selector (HDR) и LUT/OCIO-докер — выключены в CMake;
- импорт видео как анимации (нет бинарника FFmpeg);
- G'MIC (`qmic`) — требует отдельное приложение gmic-qt;
- «Открепить холст», несколько окон.
По каждому пункту будет решение или подробное объяснение в отчёте
(см. риски).

## 2. Архитектура

**Отдельный модуль, минимум правок upstream.** Весь новый интерфейс — новый
каталог `plugins/extensions/mobileui/` (плагин типа `Krita/ViewPlugin`, такие
плагины Krita уже грузит для каждого окна) плюс `mobilefork/` для CI,
документов, инвентаря и переводов. В upstream-файлах — только короткие,
помеченные `Krita Mobile (unofficial fork)` вставки: пункт настройки
«Интерфейс телефона», замена стартовой страницы, пара хуков в
`KisMainWindow`. Цель — держать изменения upstream-файлов в пределах
нескольких десятков строк, чтобы слияние новых версий Krita было рутинным.

**Технология: Qt Widgets, с заделом на QML.** Холст Krita, докеры и диалоги —
виджеты Qt 5. Прототип upstream на QML/Qt 6 не может рисовать и на Android
сейчас не собирается. Поэтому оболочка телефона делается на виджетах (как в
вашем форке Drawpile — его компоненты и дизайн переносятся), а там, где
upstream уже перешёл на QML (свойства текста, всплывающие панели), QML-панели
просто показываются внутри листов. Когда upstream переведёт параметры
инструментов на QML, они автоматически попадут в листы — дублировать их я не
буду.

**Как устроен режим телефона.**
- `KisMainWindow` остаётся: в нём живут все действия, докеры, менеджер
  холстов. В режиме телефона плагин прячет строку меню, панели и области
  докеров и накладывает поверх холста свою оболочку.
- Докеры не переписываются заново (иначе функции неизбежно потеряются): их
  виджеты переносятся в нижние листы (портрет) / боковые панели (альбом), а
  листы добавляют крупные элементы, жесты закрытия и адаптивную вёрстку.
  Для самых частых (слои, кисти, цвет, таймлайн) делаются удобные мобильные
  «карточки» поверх тех же моделей данных, с кнопкой «полная панель».
- Все меню генерируются из живого `guiFactory()` → сгруппированные листы и
  палитра команд (на базе существующего `KisCommandBar`), поэтому новые
  действия upstream появятся автоматически.
- Режим выбирается автоматически по наименьшей стороне экрана (< 600 dp) и
  переключается в настройках; настольный/планшетный интерфейс не меняется.
- Масштаб: в режиме телефона включается 1 логический пиксель = 1 dp, а
  оболочка сама задаёт размеры (касание ≥ 48 dp), без системного «2–3×».

**Оформление.** Те же токены, что в Drawpile Mobile (тёмная/светлая палитры,
скругления, иконки в одном стиле), учёт вырезов и системных панелей,
сохранение состояния при повороте.

## 3. CI на GitHub Actions

Файл `.github/workflows/mobilefork-android.yml`, ветка `mobile`:
1. Освобождение диска (удаляются .NET, GHC, лишние NDK — ~25 ГБ).
2. SDK/NDK ставятся из предустановленного на раннере Android SDK
   (NDK 27.3.13750724, build-tools 36, platform 36).
3. Скачиваются готовые зависимости KDE из реестра invent.kde.org (без
   сборки Qt и прочего с нуля). Отдельный шаг заранее проверяет, что реестр
   доступен анонимно, чтобы ошибка была понятной.
4. Сборка Krita (Release, без тестов), ccache в кэше Actions.
5. APK через тот же скрипт, что у upstream; подпись ключом из секретов или,
   если секретов нет, тестовым ключом из кэша (тогда новые сборки всё равно
   ставятся поверх старых).
6. Результаты: pre-release `mobile-build-N` с APK (скачивается на телефоне без
   входа в GitHub), артефакт, и **ветка `ci-status`** с итогом и хвостами
   логов. Её я читаю обычным `git fetch` — вам не придётся пересылать логи,
   кроме случаев, когда упадёт сама публикация статуса.
7. Позже (фаза 2+) — второй job: сборка Krita для Linux с той же оболочкой и
   автоматический прогон в окне размера телефона: скриншоты всех экранов в
   портрете и альбоме, обход инвентаря (каждое действие должно находиться
   через интерфейс), юнит-тесты upstream. Скриншоты тоже уходят в `ci-status`.
   Так я проверяю многое сам, а на телефоне вы проверяете то, что эмулировать
   нельзя (стилус, производительность, жесты, файлы Android).

Оценка времени: первая сборка ~2,5–4 ч (лимит 6 ч), с ccache — заметно
быстрее.

## 4. Фазы

| Фаза | Результат | Что проверяете вы |
|---|---|---|
| 0 | Карта кода, инвентарь, этот план | Согласовать план |
| 1 | APK `org.krita.mobilefork` ставится на телефон, старый интерфейс | Установка, запуск, базовые замеры |
| 2 | Оболочка телефона: стартовый экран, холст, панель инструментов, быстрые ползунки, листы слоёв/кистей/цвета/таймлайна, меню + поиск, темы | Удобство, жесты, повороты |
| 3 | Остальные докеры, параметры инструментов, диалоги (фильтры, редактор кисти, экспорт, рендер анимации, настройки) под телефон; переводы ru/uk | Полнота, тексты |
| 4 | Оптимизация без изменения результата: запуск, память, холст GLES, задержка штриха, открытие панелей | Замеры против фазы 1 |
| 5 | Тесты, обход инвентаря, баги, итоговый отчёт с скриншотами | Финальная проверка |

## 5. Риски и запасные пути

1. **Реестр зависимостей KDE недоступен анонимно** (главный риск фазы 1). —
   Запасной путь: собирать зависимости самим через `krita-deps-management`
   отдельной цепочкой job'ов, каждый < 6 ч, с кэшем; первая сборка тогда
   займёт несколько прогонов, потом — только Krita.
2. **Скрипты KDE CI рассчитаны на их VM-образ** (переменные из
   `/var/lib/ci-files/setup-environment.sh`). — Переменные выставлены в
   workflow вручную; если чего-то не хватит, будет видно в `ci-status`.
3. **Нехватка диска/времени на раннере.** — Очистка диска, ccache,
   кэш скачанных зависимостей, при необходимости разделение на job'ы.
4. **Python-плагины на Android.** Upstream их не собирает. Включить можно
   только собрав Python + SIP + PyQt5 под Android (сложно, +50–80 МБ APK).
   Предложение: сначала всё остальное; Python — отдельной задачей в фазе 3–4
   с честной оценкой, работает ли.
5. **G'MIC.** На настольных системах это отдельный процесс gmic-qt; на
   Android запустить чужой бинарник нельзя. Решение — встроить libgmic как
   библиотеку (объём и лицензия CeCILL совместимы с GPL) — оценю в фазе 3.
6. **Импорт видео.** Нет FFmpeg-бинарника; есть MediaCodec (уже используется
   для экспорта) — можно сделать импорт через него.
7. **HDR-селектор цвета и LUT/OCIO-докер.** Выключены upstream на Android;
   попробую включить (OCIO в зависимостях есть) и проверить.
8. **Производительность и память телефона.** Krita рассчитана на ПК; узкие
   места — запуск (загрузка ресурсов), лимит памяти тайлов, свап во
   внутреннем хранилище. Меняю только значения по умолчанию для телефона,
   всё остаётся настраиваемым.
9. **Слияние с upstream.** Если upstream активно меняет `KisMainWindow` или
   переедет на Qt 6, хуки придётся переносить; поэтому их мало и они
   помечены. Описание процедуры слияния — в отчёте.
10. **Лицензии.** Новый код — GPL-3.0-or-later (как и код из Drawpile Mobile,
    который будет перенесён), все авторские права и credits Krita
    сохраняются; в «О программе» и на стартовом экране явно сказано, что это
    неофициальная сборка.
